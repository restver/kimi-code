### 2.1 turn 级文件历史快照（实验）`#3339`

本批最大的新功能，+2144 行。解决的问题：想知道"第 N 轮对话把哪些文件改成了什么样"，以前只能从工具调用参数里反推（Edit 的新旧文本片段拼起来），既不可靠也查不了历史。现在引擎自己存快照：

- **存什么**：Edit/Write 工具执行前（tool executor 的 will-execute 钩子，赶在任何写入前，不与读竞争）把被碰文件的**整份原内容**存成 blob（blob＝一整份文件内容的存储块）；主 agent 每个 turn 边界各做一次 checkpoint（检查点——某一边界时刻全体被跟踪文件的版本记录；轮开始一次、轮结束一次）——**用户在两轮之间手改的文件不属于任何一轮**，这个边界设计就是为此（提交说明原文："so edits the user makes between turns attribute to no turn"）。

- **省空间**：没变的文件按内容 hash 去重（同一份内容只存一个 blob）；超过 4 MiB 的文件不存内容，改存"size+mtime 指纹"的 oversize 哨兵值（哨兵值＝一个不代表内容、只代表"这文件超大没存"的占位记录）；checkpoint 事件做 delta 编码（只存与上一检查点的差异）并折回可重放的 agent state。

- **查什么**：`changes()`（某一轮的逐文件增删行）从 blob 现场计算，与写入串行；逐行 diff 用 LCS（最长公共子序列，逐行比对的经典动态规划算法）算，带预算——单文件 4M 格、单次调用合计 16M 格，超预算的文件落 oversize 无计数标记，防止一轮重写几百个文件把服务器事件循环卡死。

- **留多久**（flag 自述原文）：每个 workspace 最近 30 个活跃会话、各自最近 5 个编辑 turn；实现在 `packages/agent-core-v2/src/features/fileHistory/fileHistoryRetention.ts`。

- **开关**（默认关，`packages/agent-core-v2/src/features/fileHistory/flag.ts:4-6`）：

  ```ts
  export const FILE_HISTORY_FLAG_ID = 'file_history';
  export const FILE_HISTORY_FLAG_ENV = 'KIMI_CODE_EXPERIMENTAL_FILE_HISTORY';
  ```

- **REST 面**（`packages/kap-server/src/routes/fileHistory.ts:38,80`）：

  ```ts
        path: '/sessions/{session_id}/file-history/changes',
        path: '/sessions/{session_id}/file-history/content',
  ```

  changes 返回某一轮的逐文件增删；content 返回某文件在某个 checkpoint 边界的完整内容。已持久化的冷会话按需 resume（与 transcript 路由的冷会话行为一致）。核心实现 694 行在 `fileHistoryService.ts`。

### 2.2 强制停止后的 handoff 步骤 + 子代理停止原因 `#3459`

以前工具调用重复保护（repeat breaker，检测到模型反复发同一工具调用时强制停轮的机制）一触发，turn 直接死掉，用户只能看到失败。现在触发后 loop 会补跑**一个 handoff 步骤**（handoff＝交接，让模型把已完成的工作总结成文字再走），该步骤只许输出文本、再发工具调用会被拒绝：

### 4.1 遥测上下文重建成"按作用域分层的注册表" `#3430`
